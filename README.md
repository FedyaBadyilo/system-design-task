# Автоматизация обработки тикетов — PoC

Локальный вертикальный срез AI-контура поддержки. Он принимает
валидированный mock-тикет, удаляет формализованные PII, оценивает тему, риск и
уверенность, ищет одобренную статью, формирует helpdesk payload либо передаёт
тикет оператору и сохраняет объяснимый audit trail в SQLite.

Быстрая классификация отделена от retrieval и генерации интерфейсами
`make_fast_decision()` и `process_generation_job()`. В PoC они вызываются
последовательно; в целевой архитектуре второй этап выполняется асинхронно.

## Бизнес-ценность

Около 40% обращений считаются типовыми, поэтому безопасная автоматизация
сокращает повторяющуюся работу операторов и освобождает часть из 8 минут,
которые сейчас в среднем тратятся на тикет. Каждый полностью
автоматизированный случай потенциально экономит до 150 ₽ валовых затрат до
учёта inference, эксплуатации и повторных обращений. Быстрая маршрутизация и
асинхронная подготовка ответа помогают удерживать SLA первого ответа 15 минут,
в том числе при всплесках нагрузки. Приоритет — увеличивать долю безопасно
решённых тикетов без ухудшения текущих CSAT 4,2/5 и reopen rate 9%; PoC
демонстрирует механизм, но не подтверждает фактический эффект.

## Локальный запуск

Требуется Python 3.11 или новее.

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -e ".[dev]"
./.venv/bin/support-ai-demo --deterministic
./.venv/bin/python -m pytest
```

Demo показывает:

- безопасный happy path с `AUTO_REPLY_READY` и ссылкой на статью;
- платёжный тикет, который сразу получает `HUMAN_REVIEW`;
- low-confidence abstention;
- деградацию в `HUMAN_REVIEW` при недоступной генерации.

CLI печатает фактически выполненные этапы и итог для helpdesk. Audit сохраняется
в игнорируемой Git базе `.data/audit.db`.

## Реальный LLM

Опциональный OpenAI-compatible адаптер настраивается через `.env.example` и
запускается командой `support-ai-demo --scenario happy`. Он допустим только для
синтетических примеров: regex не гарантирует удаление контекстных PII. Ошибка,
timeout или невалидный ответ приводят к `HUMAN_REVIEW`, а не к mock-успеху.

## Что реализовано, а что замокировано

- **Реализовано:** контракты, regex-очистка PII, policy, TF-IDF retrieval,
  генерация и проверки ответа, идемпотентность, SQLite-аудит.
- **PoC-замены:** keyword-классификатор, локальная база знаний и
  детерминированный генератор.
- **Только дизайн:** обученная модель темы, локальный PII detector, очередь,
  управляемая база знаний и интеграция с helpdesk.

## Допущения

- Компания уже использует омниканальную helpdesk-систему как источник истины;
  PoC не реализует channel adapters и отправку ответа.
- Для MVP доступна одобренная и версионируемая база знаний; локальный JSON
  имитирует этот источник.
- Автоматизация начинается с нескольких безопасных информационных тем.
  Платежи, доступ к аккаунту, security, legal и safety всегда требуют человека.
- Все примеры PoC синтетические; качество моделей, пороги и бизнес-эффект должны
  быть подтверждены на данных и в ограниченном пилоте.

## Ограничения

- Тестовые статьи и keyword-правила не доказывают качество модели.
- Нагрузка 200 тысяч тикетов в день и целевая задержка не проверялись.
- Ответ считается готовым к отправке, но PoC не отправляет и не закрывает тикет.
