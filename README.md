# Автоматизация обработки тикетов — PoC

Локальный вертикальный срез AI-контура поддержки. Он принимает
валидированный mock-тикет, удаляет формализованные PII, оценивает тему, риск и
уверенность, ищет одобренную статью, формирует helpdesk payload либо передаёт
тикет оператору и сохраняет объяснимый audit trail в SQLite.

Быстрая классификация отделена от retrieval и генерации интерфейсами
`make_fast_decision()` и `process_generation_job()`. В PoC они вызываются
последовательно; в целевой архитектуре второй этап выполняется асинхронно.

## Бизнес-ценность

Около 40% обращений считаются типовыми, поэтому безопасная автоматизация
сокращает повторяющуюся работу операторов и освобождает часть из 8 минут,
которые сейчас в среднем тратятся на тикет. Каждый полностью
автоматизированный случай потенциально экономит до 150 ₽ валовых затрат до
учёта inference, эксплуатации и повторных обращений. Быстрая маршрутизация и
асинхронная подготовка ответа помогают удерживать SLA первого ответа 15 минут,
в том числе при всплесках нагрузки. Приоритет — увеличивать долю безопасно
решённых тикетов без ухудшения текущих CSAT 4,2/5 и reopen rate 9%; PoC
демонстрирует механизм, но не подтверждает фактический эффект.

## Локальный запуск

Требуется Python 3.11 или новее.

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -e ".[dev]"
./.venv/bin/support-ai-demo --deterministic
./.venv/bin/python -m pytest
```

Demo показывает:

- безопасный happy path с `AUTO_REPLY_READY` и ссылкой на статью;
- платёжный тикет, который сразу получает `HUMAN_REVIEW`;
- low-confidence abstention;
- деградацию в `HUMAN_REVIEW` при недоступной генерации.

Для каждого примера CLI печатает входной mock-запрос, только фактически
выполненные этапы и краткий итог для helpdesk. JSON-контракты остаются внутри
приложения и тестов.

Собственный синтетический запрос можно передать отдельно:

```bash
./.venv/bin/support-ai-demo \
  --text "Не приходят уведомления, как их включить?" \
  --deterministic

./.venv/bin/support-ai-demo \
  --text "С карты дважды списали деньги" \
  --channel web \
  --selected-topic payments \
  --deterministic
```

SQLite создаётся в `.data/audit.db` и не попадает в Git.

## Реальный LLM

Скопируйте `.env.example` в `.env` и заполните:

```text
LLM_BASE_URL=...
LLM_API_KEY=...
LLM_MODEL=...
```

После этого happy path использует один OpenAI-compatible вызов:

```bash
./.venv/bin/support-ai-demo --scenario happy
```

Ключ не выводится и не сохраняется в audit. Во внешний LLM передаются
обработанный regex-правилами текст и найденные фрагменты базы знаний, но regex
не гарантирует удаление контекстных PII. Поэтому live-режим предназначен только
для синтетических примеров и не должен использоваться с реальными обращениями
до появления локального PII detector. Невалидный ответ, timeout или ошибка
провайдера не подменяются успешным шаблоном: тикет передаётся оператору.

## Что реализовано, а что замокировано

Реально работают Pydantic-контракты, regex-очистка PII, policy, TF-IDF retrieval,
структурированная LLM-генерация, проверки ответа, идемпотентность и
нормализованный SQLite-аудит. Keyword-классификатор, локальная база знаний и
детерминированный генератор — явно обозначенные PoC-замены.

В целевой системе вместо них используются обученный и откалиброванный
`TF-IDF + Logistic Regression`, управляемая база знаний, локальный PII detector,
очередь и интеграция с helpdesk. UI, HTTP API и Docker намеренно не входят в
этот PoC.

## Допущения

- Компания уже использует омниканальную helpdesk-систему как источник истины;
  PoC не реализует channel adapters и отправку ответа.
- Для MVP доступна одобренная и версионируемая база знаний; локальный JSON
  имитирует этот источник.
- Для обучения целевой модели доступны исторические тикеты с итоговыми темами
  и использованными статьями; эти операторские метки считаются шумными.
- Автоматизация начинается с нескольких безопасных информационных тем.
  Платежи, доступ к аккаунту, security, legal и safety всегда требуют человека.
- Все примеры PoC синтетические; качество моделей, пороги и бизнес-эффект должны
  быть подтверждены на данных и в ограниченном пилоте.

Подробные допущения приведены в [продуктовом контексте](docs/product.md).

## Ограничения

- Тестовые статьи и keyword-правила не доказывают качество модели.
- Нагрузочные характеристики 200 тысяч тикетов в день проверены только
  архитектурно, а не этим локальным процессом.
- Ответ считается готовым к отправке, но PoC не отправляет и не закрывает тикет.
- Реальный провайдер может отвечать нестабильно; безопасный fallback проверен.
